# Open TTS v1.10.2

This release fixes Qwen3 on Apple Silicon, where sampling had quietly become
greedy decoding and some Reader passages failed outright. It also makes the
Reader and audiobook export work smoothly with Qwen3, and moves the Rust bridge
to a Cargo workspace with Windows and dependency checks in CI.

## Qwen3 on Apple Silicon (MLX)

- Qwen3 samples again. The top-k cutoff was read from index `k - 1` of the
  top-k values, which assumes they are sorted, but MLX returns them in
  partition order. The cutoff was often the single most likely code, so every
  run and every seed decoded the same audio. Greedy decoding can loop: a PDF's
  print header never reached end-of-speech, hit the frame limit, and failed its
  whole Reader section, and trying again could not help. The cutoff is now the
  true k-th largest value, in both the talker and the code predictor.
- Each text unit reaches the model single-spaced with no surrounding
  whitespace, as the reference implementation's input is.
- Voice Clone streaming primes the vocoder with the last 25 frames of the
  reference clip, as the reference decoder does, so each passage starts in the
  cloned voice instead of from a cold decoder.

## Reader and audiobook export

- Hard-wrapped imports such as PDFs are read as whole sentences: a line wrap
  becomes a space and an unpunctuated heading or byline gets a full stop.
  Highlighting and progress offsets are unchanged.
- The next-section look-ahead and each audiobook export section no longer fail
  with "Too many generation requests" when they start right after the previous
  generation. They wait out the rest of the 500 ms cooldown instead.
- While Qwen3 generates, word highlighting, click-to-seek, and sentence steps
  stay word-accurate in passages that have finished generating.
- The Voice Clone passage count matches what plays.
- A failed Qwen3 passage is reported as a generation error, not as a setup
  problem.

## Rust bridge and CI

- `rust/` is a Cargo workspace. The model-free bridge code is the
  `open-tts-bridge-core` crate, with one shared `Cargo.lock` and lint settings.
- The bridge no longer compiles the vendored HTTP server and audio encoders
  (30 fewer crates); macOS builds no longer need `automake`, `autoconf`, or
  `libtool`.
- Rust 1.99.1. WebSocket TCP keepalive uses `socket2` instead of `unsafe`
  code and also applies on Windows.
- CI compiles and Clippy-lints the Windows x64 bridge, checks Rust
  dependencies with `cargo-deny`, and skips the Linux bridge test when no
  bridge input changed.
- `.gitattributes` no longer routes the vendored tree through Git LFS.

## Vendored qwen3-tts-rs

`OPEN_TTS.patch` is regenerated from the pinned upstream revision (the method
first reproduced the previous patch byte for byte) and now also covers the new
`mlx_min_axis` binding. The vendor digest is updated.

## Development checks

`npm run lint`, `npm run typecheck`, `npm test`, `npm run test:rust`,
`cargo fmt --check`, and Clippy with `-D warnings` pass on Apple Silicon. In
the desktop app, five runs of one sentence now give five different lengths
(previously identical for every seed), and the PDF that failed in the Reader
plays through without errors.

Not run for this release: a listening check of Voice Clone with the primed
vocoder, the LibTorch build of the new `amin_dim` reduction (Windows CI
compiles it), and `electron/rustLocalBridge.test.ts` end to end.

## Distribution

This is a source-only GitHub Release. GitHub supplies ZIP and tarball source
archives. On a Mac, the installer builds and installs the app; other
developers can build desktop packages locally using the documented setup and
packaging commands.
